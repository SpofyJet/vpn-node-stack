# Изменения

## 1.4.1 — установщик 1.4.1, node 1.2.1, shieldnode 1.2.0 (2026-09-26)

Исправления по отчёту с чистого сервера (Ubuntu 24.04, 6.8.0-111, 4 ГБ):
- **Ложный ✗ у `net.ipv4.tcp_mem` в «Статус оптимизации».** Значение считается от объёма RAM (MemTotal),
  а он после перезагрузки отличается на десятки КБ — план расходился с применённым значением на 1 страницу.
  Теперь `tcp_mem` округляется до целых мегабайт (одинаков между загрузками, повторный apply не переписывает
  файл), а статус допускает расхождение до 1% для этого ключа (показывает `✓≈`).
- **Отрицательные дельты в «perf since apply» после перезагрузки** (`squeeze=-0.392%`): счётчики ядра
  обнуляются при загрузке, прежняя проверка «счётчики меньше» это не ловила. Теперь сравнивается идентификатор
  загрузки: после reboot статус пишет «был reboot — дельты появятся после следующего apply».
- **«LIMIT: NIC дропает на приёме» из-за одного пакета.** Предупреждение — только если дропов ≥ 100 или
  больше 0,1% принятых пакетов.

## 1.4.0 — установщик 1.4.0, node 1.2.0, shieldnode 1.2.0 (2026-09-25)

Разбор причин и доказательства — `docs/DIAGNOSIS.md`.

### Порты и фаервол (shieldnode)
- **Инбаунды — из конфигурации Xray (API), а не из списка сокетов** (E1/E2). Раньше каждый исходящий UDP-поток
  клиента (DNS, QUIC) выглядел как «слушающий порт» и попадал в `protected_udp` (~70 мусорных портов на лабе,
  вечные WARN в проверке). Без API — осторожная эвристика (UDP-порт берётся, только если он стабилен и есть TCP-пара,
  он вне эфемерного диапазона или зарезервирован).
- **Защищаемые порты следят за реальностью** — служба `shieldnode-ports` (E3): инбаунды, UFW, SSH, API ноды;
  новый инбаунд из панели защищён в течение минуты (лаба: 17 с).
- **API ноды (2222) закрыт для всех, кроме `TRUSTED_IPS` и источников UFW** — панель остаётся подключённой.
- **Фаервол поднимается при загрузке до сети и Docker** (P0-2): `shieldnode.service` без DefaultDependencies,
  `Before=network-pre.target docker.service`. Лаба: 18.9 с (было 26.5–27.7 с — после поднятия NIC).
- **IPv6 fail-safe**: любой IPv6-пакет отбрасывается на входе и выходе, в том числе в аварийном режиме.
- `shieldnode verify` — проверка «фаервол жив» (хуки, число правил, fail-safe, наборы, IP SSH-сессии в белом
  списке); установщик завершает установку ошибкой, если verify не проходит (E8).

### Блок-листы и проверка
- Свой список больше не остаётся пустым после применения (E4): гард «тот же контент» пропускает только если
  набор в ядре непуст; то же для интервального гарда фидов.
- После перезагрузки и применения блок-листы сразу восстанавливаются из последнего снимка (раньше — пусто 2–5 мин).
- CrowdSec без решений — честный статус «ждём community-список», не сбой и не алерт; «застрявший» агент
  перезапускается не чаще раза в час, максимум 3 раза.
- Таймеры обновления (CrowdSec, фиды, очистка) больше не «умирают» после применения: раньше после `vpn-node apply`
  таймер CrowdSec не срабатывал до перезагрузки (на лабе — 3 ч без обновления).
- Журнал применения называет оба интервала (фиды — 6 ч, CrowdSec — 30 мин).
- **Пульт `guard` показывает ровно проблемы проверки `status` + `verify`** (E5: был «Проблем не найдено» при WARN=12).
- Проверка: SSH слушает, IP сессии в белом списке, заполнение conntrack, состояние IPv6 хоста.

### IPv6 (node)
- **IPv6 выключен всегда и надёжно** (E6): `ipv6.disable=1` в cmdline (grub.d), sysctl на каждом интерфейсе,
  drop-in systemd-networkd `LinkLocalAddressing=no`, Docker `"ipv6": false`. Не откатывается; переключатель в меню убран;
  `HARDEN_IPV6=0` игнорируется.

### Оптимизация (node)
- **XanMod не ставился нигде** (E7): ошибка `pipefail` в проверке «чужого источника» обрывала шаг. Исправлено;
  **XanMod теперь по желанию** (`ENABLE_XANMOD=0` по умолчанию, пункт меню с объяснением риска и перезагрузкой).
- Установка XanMod безопасна: отказ при UEFI Secure Boot (неподписанное ядро не загрузится — на лабе
  нода не поднялась), проверка места в /boot, **пробная первая загрузка** (по умолчанию остаётся штатное
  ядро, XanMod становится ядром по умолчанию только после успешной загрузки). Сравнение на лабе:
  выигрыша в скорости к пользователю XanMod не дал — остаётся по желанию.
- `netdev_budget_usecs` считается под все установленные ядра (раньше первая загрузка XanMod
  заканчивалась ошибкой systemd-sysctl).
- `ip_local_reserved_ports` резервирует реальные инбаунды из контракта shieldnode, а не случайные UDP-сокеты;
  обновляется вместе с портами (`node reserve-ports`).
- Настройка fq работала не на всех NIC: у multiqueue virtio дочерние fq под `mq 0:` неадресуемы — корневой mq
  пересоздаётся с `handle 1:`.
- fq реально ставится на сетевую карту сразу при применении (раньше — только после перезагрузки); откат
  возвращает дефолтный qdisc ядра; служба `node-fq-tune` больше не остаётся в состоянии failed после обновления.
- Drop-in `LimitNOFILE` ставится только юнитам с xray/remnanode в `ExecStart` (раньше попадал на юнит shieldnode).

### Установщик 1.4.0
- `sudo vpn-node diag` — архив диагностики (nft, сокеты, порты, IPv6, юниты и порядок загрузки, UFW, CrowdSec, sysctl,
  лимиты remnanode, ядро/GRUB, проверки) **без секретов**: SECRET_KEY, пароли, UUID, ключи, IP заменены метками;
  после очистки — проверка на утечки.
- Пост-проверка через `shieldnode verify`; итог и предложение перезагрузки учитывают IPv6.

### Производительность
- Проход синхронизации портов: 3.8 → ~1.7 с CPU (поиск портов sshd без обхода всех процессов); полный проход —
  при изменении, страховочный раз в 30 мин.

### Инструменты
- `tools/build-release.sh` — воспроизводимый архив (раскладка codeload), `SHA256SUMS`, `latest`.
- `tests/e2e/` — лаборатория (LXD: нода, панель Remnawave, клиент) и приёмка по 10 критериям (`run-acceptance.sh`).
